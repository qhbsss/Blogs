## 什么是科学上网？

因为一些原因我们在国内使用互联网访问境外某些网站时会收到限制，也就是 [GFW](https://zh.wikipedia.org/wiki/%E9%98%B2%E7%81%AB%E9%95%BF%E5%9F%8E?spm=ata.21736010.0.0.40b77536OQGk5S) 项目。具体表现为访问一些境外网站时打不开，或者一直处于加载状态拿不到数据。也就是俗称的“被墙了”。

在国内糟糕的网络环境下，很难获取真正有价值的信息。于是突破互联网限制，更好的提高自己的科学姿势，即是本文科学上网的主题。

此处划重点，科学上网是为了学习、交流、获取专业技能相关的学术信息，严禁用于非法行为以及参与政治活动。

## GFW 是什么？

> 中国第一封成功对外发出的电邮是在1987年9月14日发出，内容为“Across the Great Wall, we can reach every corner in the world”（越过长城，走向世界每个角落）。

GFW = The Great Firewall，是拦在中国网络和国际互联网之间的一堵“墙”。用于双向拦截特定流量，屏蔽指定的网络访问。并且它的能力在持续升级，拦截的范围越来越大，封锁手段越来越强。

## 为什么 GFW 可以封锁网络？

GFW 部署在中国各大网络出口，即国内网络和国际互联网之间的出入口，任何跨境流量都在它的监控之下。

![](1543654774522-5174bddf-e33a-40a4-aa75-f4.png)

##### 出口总带宽有限

> 中国大陆国际出口带宽有限，截至2018年6月为8,826,302Mbps，只有三个位于青岛、汕头和上海的海底光缆连接点，且受到防火长城的干扰，在中国大陆访问境外网站经常会变得很慢。在国际出口拥塞的情况下，运营商会自动在国际出口线路路由上使用动态QOS调整策略，把民用宽带用户的数据全部或根据拥塞情况选择性丢弃，以此给专线/企业/政府的数据让道，以此达到保证这些“VIP”用户的宽带质量。

##### IPV4 地址有限

> 全球IPv4地址数已于2011年2月分配完毕，自2011年开始中国IPv4地址总数基本维持不变，共计有33870万个。

## 哪些网站会被拦截？

并不是所有的境外网站都会拦截，比如微软、亚马逊、Airbnb、Linkedin等网站都可以正常使用。被拦截的都有一定原因，比如：Wikipedia、Google、Facebook、Twitter、Insgram 以及 Steam 上的一些血腥、暴力游戏等。总结可以发现他们都满足一定规律：

1. 违法行为：赌博、暴力、色情、诈骗、走私、盗版等，违反我国相关法律的网站。
2. 政治活动：搜索引擎、社交网站、视频网站、百科信息类网站等。

这些不满足中国互联网审查的网站都将被限制中国境内的流量访问。

## GFW 如何识别我在访问这些网站？

拦截方式分为两类：

一类是根据现有规则直接提前封锁，无需识别你是否访问这些网站，直接阻断了相关的流量通信。

另一类是主动发现型，GFW 会嗅探大家的境外访问流量的内容，根据一定的规则识别特征，发现违规流量后直接封锁相关渠道，表现为某些网站或者某些代理 IP 一开始能够使用，在访问一段时间后突然被断开（TCP RST）或者直接封锁。

具体方式又分为下面几种：

### DNS 劫持

当你使用域名访问一个网站时，首先你会通过 DNS 服务器来解析网站的 IP 地址，然后通过 IP 地址来请求真实流量。所以 DNS 劫持的方式就是篡改目标网站在国内各大 DNS 服务器的解析地址，即你在访问域名时，得到了一个错误解析的 IP 地址，最终导致你无法访问对应的网站。具体行为表现为域名无法正常访问，但是 IP 地址可以访问，并且强行切换 HOST 后可以正常访问。

解决办法：换用一些纯净无污染的 DNS 服务器。

- [PdoMo-DNS](https://pdomo.me/): 101.132.183.99 / 193.112.15.186
- [XsicoDNS](https://dns.xsico.cn/): 182.254.242.15

> 2010年4月8日，中国大陆一个小型ISP的错误路由数据，经过中国电信的二次传播，扩散到了整个国际互联网，波及到了AT&T、Level3、Deutsche Telekom、Qwest Communications和Telefonica等多个国家的大型ISP。
> 
> 2012年11月9日下午3点半开始，防火长城对Google的泛域名.http://google.com 进行了大面积的污染，所有以.http://google.com 结尾的域名均遭到污染而解析错误不能正常访问，其中甚至包括不存在的域名，而Google为各国定制的域名也遭到不同程度的污染（因为Google通过使用CNAME记录来平衡访问的流量，CNAME记录大多亦为.http://google.com 结尾），但Google拥有的其它域名如.http://googleusercontent.com 等则不受影响。有网友推测这也许是自防火长城创建以来最大规模的污染事件，而Google被大面积阻碍连接则是因为18大 。

### DNS 污染

DNS 污染位于 DNS 劫持更上游的位置，个人用户更加难以防范。

由于通常的 DNS 查询没有任何认证机制，而且 DNS 查询通常基于的 UDP 是无连接不可靠的协议，因此 DNS 的查询非常容易被篡改， 通过对 UDP 端口 53 上的 DNS 查询进行入侵检测，一经发现与关键词相匹配的请求则立即伪装成目标域名的解析服务器（NS，Name Server）给查询者返回虚假结果。

> 2010年3月，当美国和智利的用户试图访问热门社交网站如http://facebook.com和http://youtube.com还有http://twitter.com等域名，他们的域名查询请求转交给中国控制的DNS根镜像服务器处理，由于这些网站在中国被封锁，结果用户收到了错误的DNS解析信息，这意味着防火长城的DNS域名污染域名劫持已影响国际互联网。

解决方案：VPN、域名远程解析。

### HTTP 劫持

由于 HTTP 是非加密协议，是的对于各大 ISP 来说中间人攻击实施起来非常容易。中国的部分运营商也会通过此技术插入广告，比如大家使用家里的宽带或者手机蜂窝网络上网时，可能会在访问某些网站时被强行插入广告。

然而 GFW 的方式更加全面，它甚至还会根据传输数据的内容分析关键字，从而实现精准的关键字封锁。

解决方案：加密连接。

### IP 封锁

由 GFW 工作人员维护定制的 IP 访问黑名单。这是目前最森严也最难攻破的封锁方式，直接在出口路由处根据 IP 规则匹配，伪造双向数据包返回（TCP-RST），精准的封锁了 IP 访问。IP 一经加入黑名单，再也无法解封。由于大型网站都会有大量不同的 IP 供不同地区的用户访问，并且随着规模扩大他们的 IP 总数也持续增加，所有会有一些时期用户突然发现某些网站可以访问了。然而这些漏网之鱼一经发现，就将立即被加入黑名单，说明 GFW 的工作人员在网络无处不在，他们潜伏在各大社交、新闻网站中，一旦发现信息就会更新到新的防火墙规则中，所以不要在公开场合泄漏相关信息。

解决方案：代理访问。

### 端口封锁

嗅探分析流量特征比较消耗资源，GFW 无法兼顾到 IP 的所有端口流量数据，所以一些经常被用来走代理流量的端口也是重点照顾对象。严格时期甚至直接暴力封锁某些 IP 端的 22 端口，即你买了 VPS 后无法 SSH 到远程主机上做任何操作，简单粗暴的解决了境外代理服务器的风险。

目前为止，GFW 采用的是 IP 黑名单模式，比如 Google、Facebook 这类在黑名单上的网站，他们的 IP 均被精准封锁，而不在黑名单上的第三方不知名的 IP 是不会收到影响的。目前主流的“翻墙”手段都是基于上述原理实现的。

如大家熟知的：VPN、SS、SSR、V2Ray、Brook。只是它们的技术细节不同。

##### VPN 是什么？

VPN 是一个统称，它有很多的具体实现，比如PPTP、L2TP、IPSec和openvpn。VPN 出现远早于 GFW，所以它不是为了“翻墙”而生的。VPN 是一种加密通讯技术，它被设计出来的目的是数据传输安全和网络匿名。

##### Shadowsocks 是什么？

Github: [https://github.com/shadowsocks](https://github.com/shadowsocks)

Shadowsocks 同样有 Shadowsocks 协议和具体实现两个概念。协议目前有社区共同维护，而具体实现有很多，并且各个平台都有不同的客户端实现。

> Shadowsocks同样是一种代理协议，但是作为clowwindy为国人设计的专门用于翻墙的代理协议，相对于vpn，shadowsocks有着极强的隐匿性；相对于HTTP代理，shadowsocks提供了较为完善的加密方案，虽然比不上HTTPS代理和vpn，但使用的也是成熟的工业级的加密算法，普通个人用户完全不用顾虑；相对于HTTPS代理，shadowsocks的安装配置更为简单，中文社区更为活跃，中文文档教程更完善，更符合中国国情。
> 
> Shdadowsocks最初的版本是由clowwindy使用Python（一种目前非常热门的脚本编程语言）实现的。所以clowwindy的版本被称为Python版。shadowsocks有点名气之后，不同的开发者使用不同的编程语言为其写了很多分支版本。比如， [@cyfdecyf](https://github.com/cyfdecyf) 开发维护的Go版本， [@madeye](https://github.com/madeye) 开发维护的libev版本（由纯C语言编写，基于libev库开发），由 [@librehat](https://github.com/librehat) 开发维护的c++版，由 [@zhou0](https://github.com/zhou0) 开发维护的Perl版。这些版本的安装使用指南都可以在shadowsocks的官网上查阅。
> 
> 2015年，clowwindy因喝茶事件被迫停止了shadowsocks的维护，并删除了其开源在GitHub上的代码，Python版就此停滞。但其它版本仍处于维护更新中。其中，更新最频繁，新技术跟进最快的是由@madeye维护的libev版本。这里有必要说明下，目前，shadowsocks协议（请区分“shadowsocks协议”和“shadowsocks协议的具体实现”这两者的区别）是由shadowsocks社区内的成员共同维护，协议上任何新改进都是社区成员共同商讨的结果。但对这些变化，不同的版本的shadowsocks跟进速度不同。而跟进速度最快的就是我上面说的libev版。无论是 [SIP007](https://github.com/shadowsocks/shadowsocks-org/issues/42) 确认的ADEA Ciphers（一种同时进行认证和加密的算法），还是 [SIP003](https://github.com/shadowsocks/shadowsocks-org/issues/28) 引进的simple-obfs（tor开发的一种混淆插件），shadowsocks-libev都是最早引入自己软件的。

### 流量特征识别

不论是 VPN 还是 SS 类的代理，其实流量特征都很明显，很容易被识别出此类流量是用作“翻墙”，进一步嗅探流量内容，一旦发现违规流量，则 GFW 就会将代理服务器 IP 也加入黑名单。国内 IPV4 的 IP 用一个就少一个，所以有很多新手在自建“梯子”的时候技术和经验不足，轻易就暴露了将 VPS 用作“翻墙”行为，进而导致目前很多海外知名 VPS 运营商的大量 IP 都被 GFW 加入了黑名单，能用的越来越少，并且这些经常被封锁的运营商也被 GFW 列入了重点观察名单中，导致了其 IP 段的被封锁的风险极高。

### 如何设定代理规则？

##### 直连模式

不使用任何代理直接连接。

##### 全局模式

本机所有流量全部走代理，可能会导致某些国内服务不可用，国内网站变慢且浪费流量。适合在非浏览器端的临时场景使用。

##### PAC 自动模式

根据一份规则列表（如域名匹配、通配符匹配、网址正则匹配、IP匹配等），匹配了规则的网站走代理，其余走直连。

### 如何区分国内外流量？

如何区分国内外流量，来确定走代理还是直连，一直是开发者们在努力解决的问题。

##### IP 段匹配

根据 IP 段是否属于中国来判断，匹配了就直连，否则走代理。

> 对于中国路由表的来源，以往很多人推荐从 [APNIC](https://ftp.apnic.net/apnic/stats/apnic/delegated-apnic-latest) 获取，但是这个 IP 表并不是特别准确。第二个是 [IPIP.net](https://github.com/17mon/china_ip_list) 整理的中国 IP 段，两个月更新一次，推荐使用后者。

##### GFWList

目前大家维护了一份 [GFWList](https://github.com/gfwlist/gfwlist) ，使用白名单的方式运作，匹配了其中规则就走代理，其余走直接。当你发现直接连不上，而白名单里又没有时，你可以手动在本地的名单中添加你的规则。

### 如何使用适合的 DNS？

虽然用了 SS 代理可以解决 IP 被封锁的问题，但是当使用域名访问网站时，如果在 DNS 层面就被污染了导致拿到了错误的 IP，那么代理也没有用了。为了避免 DNS 解析结果被污染，我们可以使用远程服务器 DNS 解析的模式，也就是 GFWList 的模式。

但是当我们使用 IP 分流模式时，也遇到了另一个问题，我们需要解析后才能得到 IP，而此时并不知道该选择哪里的 DNS 服务器。比如我们在境内访问 Google 的时候解析到一个香港的服务器，然而此时我们的代理节点可呢是在美国境内的，此时体验就会很差。

目前的一个解决方案，对一个 DNS 请求同时进行本地解析和远端解析，若本地解析获得的是国内 IP，则采用；若不是国内 IP，则采用远端解析的结果。这个思路是基于 GFW 进行 DNS 污染时的一个特点，污染地址都是国外 IP。
