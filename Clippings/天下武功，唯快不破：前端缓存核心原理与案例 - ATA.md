## 天下武功，唯快不破：前端缓存核心原理与案例

2025-08-28发表73次浏览








你是否曾有过这样的体验：第一次打开某个网站时感觉有些慢，但再次访问时却能“秒开”？或者在地铁里信号不佳，一些常用的应用依然能流畅使用？这背后的核心魔法，就是缓存。简单来说，缓存就是浏览器将一度获取过的资源（如图片、脚本）存储在本地。当再次需要时，它能直接直接拿取，而无需再千里迢迢地向服务器请求。

缓存的核心思想是：将远程资源存储在本地，减少不必要的网络请求，从而实现“快”和“省”。 一个优秀的缓存策略，不仅能极大地提升网站的加载速度和用户体验，还能显著降低服务器的压力和带宽成本。

## HTTP 缓存机制

HTTP 缓存是浏览器最基础、最自动化的缓存机制。它完全由HTTP头部控制，分为两大策略：强缓存和协商缓存。

## 1\. 强缓存

### 策略

在缓存有效期内，浏览器不向服务器发送任何请求，直接从本地缓存读取资源。这是最快的缓存。

### 控制字段

一个资源想获得强缓存的资格，它的HTTP响应头里必须有如下控制字段之一。

- cache-control (HTTP/1.1, 优先使用)

- max-age=<seconds>：指定资源缓存的最大有效时间（秒）

- public: 资源可以被任何中间代理（如CDN、代理服务器）缓存

- private: 资源只能被最终用户的浏览器缓存

- no-cache: 注意，不是不缓存，而是“强制进行协商缓存”，即每次都必须向服务器验证

- no-store: 不缓存，浏览器和代理服务器都不会存储任何版本的资源

- expires (HTTP/1.0, 优先级低)

- 值为一个具体的过期时间点（GMT格式）。如果同时存在cache-control:max-age,expires会被忽略

### 流程

1. 浏览器加载资源

2. 检查本地缓存

3. 发现该资源的cache-control:max-age未过期

4. 直接使用缓存，不发请求

### 示例

图示是淘票票影院列表页，页面初次加载后进行刷新，直接读取了内存缓存，耗时0ms，非常快

![](https://oss-ata.alibaba.com/article/2025/08/2943a323-c063-45ba-be95-70e9490017c6.png)

cache-control：max-age=2592000,s-maxage=86400

## 2\. 协商缓存

### 策略

当强缓存失效后（或被设置为 no-cache），浏览器并不会直接丢弃缓存内容，而是会带着缓存的身份标识发起一次协商缓存请求，询问服务器资源是否有更新，由服务器决定是使用本地缓存还是返回新资源。

### 字段

- Last-Modified / If-Modified-Since

- Last-Modified: 首次响应时，服务器告诉浏览器资源的最后修改时间。

- If-Modified-Since: 再次请求时，浏览器带上这个时间，问服务器此后是否有更新。

- 缺点: 时间戳精度只能到秒；如果文件内容没变但修改时间变了，也会被认为需要更新。

- ETag / If-None-Match

- ETag: 首次响应时，服务器根据文件内容生成一个唯一的哈希值。

- If-None-Match: 再次请求时，浏览器带上这个哈希值。

- 优点: 只要文件内容不变，ETag就不变，比Last-Modified更精确、更可靠。

### 流程

1. 首次请求：服务器在响应头中返回资源的身份标识

2. 强缓存失效

3. 后续请求：浏览器在请求头中带上身份标识（带上If-None-Match或If-Modified-Since），去询问服务器。

4. 服务器判断：

- 如果资源未改变，返回304状态码，响应体为空。浏览器继续使用本地缓存。

- 如果资源已改变，返回200状态码和新的资源内容。

注意：304的优势在于节省了下载响应体的时间和带宽，这对于大文件（如JS库、大图片）来说是质的飞跃。但是，它无法节省网络请求本身的往返耗时。

## 缓存的存储位置

HTTP缓存下来的资源，会根据其使用频率和大小，存放在两个不同的物理位置。

## 1\. 内存缓存 (Memory Cache)

内存缓存是浏览器将资源存储在计算机内存中的一种缓存。它是浏览器缓存机制中最快的一种，是会话级别的，存储当前页面正在使用的、需要快速访问的资源。内存缓存中的资源被认为是“无条件新鲜”的，不需要再次进行 ETag 或时间校验。内存缓存存在的唯一目的就是快。

### 位置

- 计算机内存

### 特点

- 速度最快

- 生命周期短暂（标签页关闭即失效）

- 容量小：通常用于存储当前页面正在使用的、较小的、需要被频繁访问的资源，如脚本、字体、图片等

- 由浏览器自动管理，无法通过代码直接控制哪些资源进入内存缓存（可以通过<link rel="preload"></link>等方式建议浏览器将关键资源保留在内存中）

## 2\. 磁盘缓存 (Disk Cache)

磁盘缓存是浏览器将资源存储在计算机硬盘上的一种缓存，存储遵循HTTP缓存策略的资源，用于跨会话的复用。

### 位置

- 计算机硬盘 (HDD/SSD)

### 特点

- 速度较快：虽然比内存慢，但远快于从网络请求

- 持久性：除非缓存过期、被手动清除或被浏览器自动清理，否则它会一直存在。关闭标签页或浏览器后，磁盘缓存依然保留

- 容量大：可以存储体积较大、不常变动的文件


| 特性   | 内存缓存 (Memory Cache) | 磁盘缓存 (Disk Cache) |
| ---- | ------------------- | ----------------- |
| 存储位置 | 内存 (RAM)            | 硬盘 (Disk)         |
| 访问速度 | 最快                  | 较快                |
| 生命周期 | 临时 (标签页关闭即失效)       | 持久 (遵循HTTP头策略)    |
| 触发方式 | 被动 (浏览器自动管理)        | 被动 (由HTTP头控制)     |
| 主要目的 | 加速当前会话中的页面导航        | 加速跨会话的页面加载        |


## 浏览器检查资源缓存的过程

## 1\. 生成缓存键

浏览器根据资源的URL（可能会包括请求头中的某些字段，如vary指定的字段）生成一个唯一的标识符。

## 2\. 查找缓存存储

有了缓存键（即URL），浏览器会去不同的缓存位置查找这个键是否存在。

1. 内存缓存 (Memory Cache) 检查

- 检查过程: 浏览器会在其内存缓存的哈希表或类似数据结构中，快速查找是否存在与当前URL匹配的条目

- 如果命中，直接使用，速度最快，加载过程几乎瞬间完成

2. 磁盘缓存 (Disk Cache) 检查

- 在内存缓存中没有找到匹配项时，浏览器会继续检查磁盘缓存。浏览器会访问硬盘上的缓存数据库或文件系统，它会用URL作为键，查询这个数据库

## 3\. 验证缓存条目的有效性

- 如果磁盘缓存命中，根据HTTP缓存策略（强缓存/协商缓存）决定是直接使用还是向服务器验证

- 强缓存：浏览器会直接从磁盘中读取资源内容，然后加载它。不发送任何网络请求。Network面板看到的状态码会是200，并显示为disk cache

- 协商缓存流程，从元数据中提取身份标识，放入新的请求头中，然后向服务器发起网络请求

## 4\. 发起网络请求

- 如果内存缓存和磁盘缓存都未命中，浏览器才会向服务器发起网络请求，下载全新的资源

## 如何使得强缓存失效？

## 缓存自然过期

这是强缓存设计的本意。当浏览器再次请求一个资源时，它会检查该资源的HTTP响应头中的过期信息。如果发现当前时间已经超过了设定的过期时间，强缓存就会失效。

具体由以下两个HTTP响应头字段控制：

1. Cache-Control: max-age=<seconds>(HTTP/1.1, 优先)。浏览器会记录资源被获取的时间。当前时间-资源获取时间>max-age时，强缓存失效。

2. Expires: <date>(HTTP/1.0)。浏览器将当前时间与expires头中指定的绝对过期时间进行比较。如果当前时间>Expires时间，强缓存失效。注意: 由于它依赖于客户端的系统时间，如果用户本地时间不准，可能会导致缓存判断错误。因此 Cache-Control是更可靠和推荐的方式。

## 用户手动刷新

用户在浏览器中的特定操作会主动让强缓存失效，即使它还没自然过期。

1. 点击刷新

- 主文档（HTML页面）: 忽略强缓存，发起一次协商缓存请求，以确保页面入口是新鲜的。子资源（如带哈希的JS/CSS）: 如果主文档未变（服务器返回304），浏览器会基于优化策略，认为这些子资源也未变，从而继续使用它们的强缓存（优先从内存缓存加载），避免了不必要的网络验。

![](https://oss-ata.alibaba.com/article/2025/08/f8fc4410-dbaf-44db-beae-650853750346.png)

点击普通刷新后

2. 强制刷新

- 最彻底的刷新。它会完全忽略所有缓存（包括强缓存和协商缓存），直接向服务器请求全新的资源。浏览器会像第一次访问一样，下载所有内容。

![](https://oss-ata.alibaba.com/article/2025/08/8159b2bf-c85e-4a29-8f54-81f5f1df58ff.png)

强制刷新后

## 开发者主动破坏缓存

为什么要主动破坏缓存？这是确保用户获取最新资源的核心手段。开发者可以通过改变资源的URL，让浏览器认为这是一个全新的资源，从而旧的强缓存因为URL不匹配而自然失效。

最常见的“缓存破坏”技术有：

1. 文件名哈希

- 现代构建工具（如Webpack, Vite）在打包时，会根据文件内容生成一个唯一的哈希值，并将其作为文件名的一部分。

- 对于浏览器来说，这是一个全新的URL，它本地没有这个文件的缓存，于是会直接发起网络请求。旧的资源的缓存就自然作废了（直到它过期被浏览器清理）。

2. 查询参数

- 原理：在资源URL后面附加一个版本号或随机数。原本的css文件url为style.css?v=1.1。当CSS文件更新后，HTML中引用的URL改为style.css?v=1.2，浏览器同样认为这是一个新URL，从而请求新文件。

- 注意: 这种方法不如文件名哈希可靠，因为一些代理服务器或CDN可能会忽略查询参数，导致返回旧的缓存内容。

## 缓存策略

除了浏览器自动的行为，我们可以通过代码主动实施更高级的缓存策略。

## 预缓存

- 定义：一种主动的、有预见性的缓存行为。在用户实际需要某个资源之前，就提前将其下载并存入缓存中。

- 目的：极大地加快用户后续页面的加载速度，或实现应用的核心离线访问能力。

- 实现方式：

- 声明式预缓存：通过<link rel="preload">/<link rel="prefetch">，声明式提示浏览器提前下载资源。

- 指令式预缓存。开发者控制资源加载时期。比如使用fetch API请求资源，动态创建一个<image>=标签并设置其src来预加载图片。

- Service Worker: 在install事件中定义一个资源列表（“App Shell”），SW会立即下载它们。

## 其他浏览器存储 (作为数据缓存)

除了上述用于缓存网络响应的机制，浏览器还提供了一些API用于存储应用数据，也可以广义地看作一种缓存。这类存储提供了API，允许开发者用JavaScript代码主动地、精细地控制数据的存取。它们通常不直接用于缓存整个网络请求的响应体，而是用于存储应用的状态、用户数据、配置等。

## 1\. LocalStorage

- 位置: 磁盘

- 特点:

- 持久化: 数据会一直存在，除非被手动或代码清除

- 同源策略: 数据在同一源（协议、域名、端口）下的所有标签页和窗口之间共享

- API简单: 只有setItem、getItem等简单的键值对操作

- 只能存储字符串: 存储对象需要JSON.stringify()，读取时需要JSON.parse()

- 容量限制: 通常为5MB左右（因浏览器而异）

- 同步操作: 它的API是同步的，如果在主线程进行大量读写，可能会阻塞UI

## 2\. SessionStorage

- 位置: 通常在内存中，但具体实现由浏览器决定

- 特点:

- 会话级别: 数据只在当前浏览器会话（一个标签页及其中的iframe）内有效。关闭标签页或浏览器，数据即被清除

- 非共享: 在同一源的不同标签页之间，SessionStorage不共享

## 3\. IndexedDB

- 位置：磁盘

- 特点：

- 强大的客户端数据库: 它是一个完整的、事务性的、面向对象的NoSQL数据库

- 大容量: 存储容量非常大（通常可以达到GB级别或更多，取决于磁盘空间）

- 异步API: 所有操作都是异步的，不会阻塞主线程，适合处理大量数据

- 支持复杂查询: 支持索引、游标等，可以进行高效的数据查询

- 可以存储多种数据类型: 包括文件、Blob、复杂的JavaScript对象等

- API复杂: 相对于LocalStorage，其API学习成本较高

- 用途：需要在客户端存储大量结构化数据、实现离线数据编辑的核心数据库

## Service Worker Cache

这是一个完全独立于HTTP缓存的机制，是PWA（渐进式Web应用）的核心。通过一段运行在浏览器后台的JavaScript脚本（即Service Worker），开发者可以完全编程控制网络请求的拦截和响应。

- 位置: 磁盘。这是一个非常重要且特殊的存储位置。它物理上存在于硬盘，但完全独立于上面提到的HTTP磁盘缓存。

- 特点:

- 完全可编程: 开发者可以通过Service Worker的cache API 完全控制缓存的读写、更新和删除策略

- 持久化: 除非代码主动删除，否则会一直存在

- 与Service Worker绑定: 它的主要应用场景是配合Service Worker拦截网络请求，实现离线访问等高级功能

- 可以存储完整的request和response对象，这是它与localStorage等存储最大的不同，使其非常适合用于网络请求的缓存

## CDN 缓存

CDN 本质上是一个位于用户和源服务器之间的、地理上分布的代理服务器网络。

- 原理：当用户请求资源时，请求会被导向离用户最近的CDN节点。如果该节点有缓存，则直接返回；如果没有，它会向源服务器请求资源，缓存下来后再返回给用户。

- CDN节点同样遵循HTTP缓存策略，来决定自己在自己的服务器上缓存多久。
