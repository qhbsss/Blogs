## 背景

在学习前端的过程中，发现自己对一些背景不了解，不免产生一些疑问，比如总是看到HTML5，它具体指的是什么，为什么一起使用的是CSS3而不是CSS5，ES6又是什么？以前总听前端同学骂IE，最近好像很少听说了，是IE变好了吗？

为了搞清楚这些问题，翻了一下前端的历史，看看现在的前端体系如何逐渐完善的，都经历过哪些阶段。

## 前端标准的诞生

前端的能力=前端三剑客（HTML、CSS、JavaScript）的能力+ 容器（浏览器）的解释能力。

> HTML是人的构造，决定了人体有什么构成，胳膊、四肢、头...
>
> CSS是衣服和化妆品，决定了长相和外观，同一个人，妆前妆后差别还是很大的，
>
> Javascript是灵魂，决定了这个人有什么能力，写一个控制双腿行走的方法，这个人就会走路了，
>
> 浏览器是最终解释者，就算你穿了阿迪达斯，浏览器也可以画成阿迪王

**万维网联盟**

万维网联盟（World Wide Web Consortium），又称W3C理事会，该组织制定了以上语言的规范，开发中使用的导则和解释引擎的行为等等，试图通过制定并督促网络应用开发者和内容提供者遵循这些标准，解决网络应用中不同平台、技术和开发者带来的不兼容问题，保障网络信息的顺利和完整流通，但是，其作为半自治非政府组织，话语权有限，制定的网络标准 **并非强制实施，只是推荐标准** 。

比如微软在开发IE浏览器时没有遵循这个标准，就出现了兼容问题，用最新版本的语言特性写的网页，运行在低浏览器版本上，也会有兼容问题。

## HTML

HTML即HyperText Markup Language，超文本标记语言，它是Web的基石，只用它就可以写出简单的网页，其发展历史如下：

> - HTML 1.0 —— 在 1993 年 6 月作为互联网工程工作小组工作草案发布
> - HTML 2.0 —— 1995 年 11 月发布
> - HTML 3.2 —— 1997 年 1 月 14 日，W3C 推荐标准
> - HTML 4.0 —— 1997 年 12 月 18 日，W3C 推荐标准
> - HTML 4.01—— 1999 年 12 月 24 日，W3C 推荐标准
> - HTML 5 —— 第一份正式草案于 2008 年 1 月 22 日公布，正式版本发布于 2014 年 10 月 29 日

经常提到的HTML5，就是HTML的最新推荐标准，带来的主要新功能如下：

[**canvas**](https://www.runoob.com/html/html5-canvas.html)

用于绘画的canvas元素，就像一张白纸，开发者只要拿到这个canvas，就可以直接在上面作画，通过getContext("2d")，可以拿到一个二维画笔绘制2D图形，像图表折线图等，getContext("3d")可以拿到基于 WebGL图形接口的三维画笔绘制3D图形，实现编辑器、游戏等。在canvas出现之前，类似的需求，一般通过Flash实现。

<!DOCTYPE HTML>
```javascript
<html>
<head>
<title>HTML5 – Hello World</title>
</head>
<body>
<canvas id=”canvas” width=”800″ height=”600″>
  <script>
        var canvas = document.getElementById("canvas");
    var context = canvas.getContext("2d");
    context.fillStyle = "red";
    context.fillRect(0,0,100,100);
    context.strokeStyle = "blue";
    context.strokeRect(120,0,100,100);
    </script>
</canvas>
</body>
</html>
```

[**多媒体控件**](https://www.runoob.com/html/html5-video.html)

在HTML5出现之前，网页多媒体的播放，需要借助Flash插件，使用不便发热严重，HTML5内置多媒体控件video和audio，无需安装任何额外的插件即可直接播放视频音频。

[**访问位置**](https://www.runoob.com/html/html5-geolocation.html)

可以通过navigator.geolocation.getCurrentPosition接口请求用户共享他们的位置。

[**WebSocket**](https://www.runoob.com/html/html5-websocket.html)

HTML5提供的一种在单个 TCP 连接上进行全双工通讯的协议，使得客户端和服务器之间的数据交换变得更加简单，浏览器通过 JavaScript 向服务器发出建立 WebSocket 连接的请求，连接建立以后，客户端和服务器端就可以通过 TCP 连接直接交换数据，允许服务端主动向客户端推送数据。

[**Web Workers**](https://www.runoob.com/html/html5-webworkers.html)

众所周知JavaScript是单线程的，当在 HTML 页面中执行脚本时，页面的状态是不可响应的，直到脚本已完成。

web worker 是运行在后台的 JavaScript，独立于其他脚本，不会影响页面的性能。用户可以继续做任何愿意做的事情：点击、选取内容等等，而此时 web worker 在后台运行。

[**语义化标签**](https://www.runoob.com/html/html5-semantic-elements.html)

无语义化的标签即\<div>和\<span>这种，里面可以放任何内容，单纯的表明这是一个内容区域，但是里面是什么类型并不明确。

有语义化的标签即\<form>, \<header>,\<img>,\<nav>等这种，清楚的定义了它的内容，看到标签就知道这块内容区域里面放到是什么内容类型。

这样开发者在维护时更好理解，搜索引擎爬虫在解析时也能理解页面元素里的内容。

![image.png](https://oss-ata.alibaba.com/article/2023/11/9e047eb1-81e8-437c-a79b-dab16bf4a8dc.png?x-oss-process=image/resize,m_lfit,w_1600/auto-orient,1/quality,Q_80/format,avif/ignore-error,1 "image.png")

以上只是HTML5新增特性的几个举例，还有更多其他特性，比如支持svg、本地存储、表单等，都是现在前端开发中十分常用的，有兴趣可以自行了解。

上面提到的是狭义的HTML5的定义，仅代指HTML最新版本的标准，更多时候提到的HTML5其实是广义的含义，指的是包括HTML5、CSS和JavaScript在内的一套技术组合，这套技术组合丰富并增强了Web自身的能力，能够减少浏览器对Adobe Flash、Microsoft Silverlight与Oracle JavaFX的依赖。

在HTML5面世之后，大家写Flash正写的正如火如荼，用Flash还是用HTML5当时也是一个技术选择，在推动HTML5的过程中，苹果也发挥了一定的作用，乔布斯还 [发文](https://apple4us.com/2010/jobs-thoughts-on-flash-chinese) 痛批了Flash的私有性、安全性差、功耗高、移动设备触摸体验差，苹果的移动设备不再支持flash。

## CSS

CSS即Cascading Style Sheets，层叠样式表，是一种用来为HTML文档添加字体、间距和颜色等样式的语言，其发展历史如下：

> **CSS1** —— 1996年，支持网页的基本属性:字体、颜色、补白、基本选择器等，display的可选项有：none、inline、block、list-item；
>
> **CSS2** —— 1998年，，支持高级功能：浮动和定位、高级选择器等；
>
> **CSS2.1** —— 2004年 ，display的可选项有：table、table-cell、table-column、table-row；
>
> **CSS3** —— 1999年开始制订，2001年5月23日W3C完成了CSS3的工作草案，主要包括盒子模型、列表模块、超链接方式、语言模块、背景和边框、文字特效、多栏布局等模块，display的可选项有flex、box、grid
>
> 2002年5月15日发布CSS3 Line模块，该模块定义了文本行模型
>
> 2002年11月7日发布CSS3 Border模块，新增背景边框功能，后被合并到背景模块中
>
> 2003年5月14日发布CSS3 Generated and Replace Content模块，定义CSS3生成及更换内容功能。
>
> ...省略n条发布记录...
>
> 2010年4月29日发布CSS3 Template Layout模块，该模块定义了模板布局模型。
>
> 2010年4月29日发布了CSS3 Generated Content For Page Media 模块，定义了分页媒体内容模型。
>
> 2010年10月5日发布CSS3 Background and Borders模块，该模块重新定义了边框和背景模型。
>
> **CSS4** —— 2011年9月29日，W3C开始设计。

因为W3C的CSS标准只是建议，并不能强制执行的，由以上发布记录可知，不同浏览器、以及相同浏览器的不同版本之间，对于标准的实现程度一定是不同的，有的提前支持了某些标准，有的还未实现，这就出现了兼容性问题。

为了解决这个问题，每个浏览器有个自己独有的前缀，如果某个浏览器支持了一个属性，其他浏览器还未支持，那么可以在属性前面加个上这个浏览器独有的前缀。

| 前缀 | 浏览器 |
| --- | --- |
| \-webkit | chrome/safari |
| \-moz | firefox |
| \-ms | ie |
| \-o | opera |

然而，支持某种特性，不代表用起来就没有问题。“能够在任何浏览器中显示”并不意味着“在任何一个浏览器中显示的效果相同”，比如IE早期没有实现W3C推荐标准，其显示效果就与别的浏览器有差异。

CSS编写人员为了尽可能在常用的各个浏览器中达到一致的版面编排，要写很多针对各个浏览器的不同的CSS代码。当版面编排很复杂时，要在各个浏览器里获取相同效果是不可能的。某个属性的支持程度，可以在 [Can i use](https://caniuse.com/) 查询，当然现在有编译插件可以在打包时，自动拼接属性前缀，解放了开发者的工作量。

## JavaScript

JavaScript是一种解释执行的语言，它的解释器被称为JavaScript引擎，是浏览器的一部分。

最早网景公司（Netscape）模仿Java设计了JavaScript，目的是为了给网页增加动态功能，为了取得技术优势，微软IE推出了JScript，CEnvi推出了ScriptEase，与JavaScript同样可在自家浏览器上运行，然而却没有一个标准来统一这 3 种不同版本的语言。

为了统一JavaScript语言的规范，就出现了ECMAScript（简称ES），ES规范的发展历史如下：


| 版本   | 官方名称   | 发布日期     | 特性                                                                         |
| ---- | ------ | -------- | -------------------------------------------------------------------------- |
| ES1  | ES1    | 1997年6月  | 第一版                                                                        |
| ES2  | ES2    | 1998年6月  |                                                                            |
| ES3  | ES3    | 1999年12月 | 添加了正则表达式。 添加了 try/catch。                                                   |
| ES4  | ES4    | 废弃       |                                                                            |
| ES5  | ES5    | 2009年6月  | 添加了“严格模式”。 添加了 JSON 支持。 添加了 String.trim()。 添加了 Array.isArray()。 添加了数组迭代方法。 |
| ES6  | ES2015 | 2015年6月  | class 模块化（export，import） arrow function Promise 添加了 let 和 const            |
| ES7  | ES2016 | 2016年6月  | Array.prototype.includes() 指数运算符**                                         |
| ES8  | ES2017 | 2017年6月  | Object.values() Object.entries()                                           |
| ES9  | ES2018 | 2018年6月  | Promise.finally()                                                          |
| ES10 | ES2019 | 2019     | Array.flat() String.trimStart() String.trimEnd()                           |


目前主流在使用的是ES6，这一版新增了很多语法特性，包括很多语法糖， [阮一峰ES6教程](http://es6.ruanyifeng.com/) 中有很详细的介绍。

因为JavaScript引擎内置在浏览器中，所以使用哪个ES版本，要看浏览器的版本是否支持，以下是主流浏览器对ES6、ES7的支持程度，目前大部分工程都是在使用ES6版本，如果想要使用更高版本也是可以的，需要配置编译插件，在编译时把语言转移成ES6或者更低版本的标准，从而获得更好的浏览器兼容性。

## 浏览器内核

浏览器内核包括渲染引擎和JS执行引擎，前者根据HTML语法渲染网页，后者解析执行JavaScript来实现网页的动态效果，最开始两者并没有区分的很明确，后来JS引擎越来越独立，内核就倾向于只指渲染引擎。

所以现在讲浏览器内核主要说的是渲染引擎。主流内核有下面几种


| 内核                  | 浏览器                                           | 开发公司      | 背景                                                |
| ------------------- | --------------------------------------------- | --------- | ------------------------------------------------- |
| Trident/EdgeHTML    | IE(Trident)Edge(EdgeHTML)                     | 微软        | EdgeHTML是Trident的优化版本， 最新Edge也投敌到Blink内核， 该内核已经灭绝 |
| Gecko               | Firefox(servo)                                | Mozilla组织 | 自研，开源                                             |
| WebKit              | Safari，Android4.4-，UC的U3，手机QQ浏览器X5内核          | Apple     | KHTML的分支                                          |
| Blink               | Chromium，Chrome，Android4.4+，Opera(2013+)，Edge | Google    | WebKit的分支                                         |
| 国产双核（Trident+Blink） | 360浏览器，猎豹浏览器，傲游浏览器...等一堆国产浏览器                 | 国内互联网公司   | 默认使用Blink， 兼容模式使用Trident                          |

后起之秀的高级浏览器（Firefox、Safari和Chrome），性能高体验好，也完美兼容W3C推荐标准，一些常用网站自然要支持所有浏览器，所以以W3C标准开发，同时兼容IE，用户自然也就渐渐开始使用这些高级浏览器，只有在部分企业网站时迫不得已切换到IE。

于是国产双核浏览器就出现了，内置性能好的Blink内核和IE的Trident内核，默认用极速模式（Blink内核），需要时切换到兼容模式（Trident内核），从而解决了切换浏览器的痛点。

## 前端工程师的诞生

回顾了W3C推荐标准和浏览器内核的历史，前端运行环境的演进已经基本了解了，那么前端技术本身，随着环境的演进，又有哪些变化呢。

## 静态页面

早期受制于浏览器以及技术、兼容性等问题，导致网页的显示效果非常的单一，几乎都是静态页。

前端的工作非常简单，说是前端，其实只是一个模板工程师，编写页面模板，然后让后端负责填充数据渲染。所以在互联网早期，前端工程师可以说是不存在，通常由后端或者是美工来兼任，前端只是后端 MVC 结构里的 V。

一次HTTP请求对应一个静态页面。当用户访问网站时，会向后台发送一个请求，后台接收到请求，生成静态HTML页面，发送到浏览器。

```java
<html>
<head><title>Hello World</title></head>
<body>
```

out.println("Your IP address is " + request.getRemoteAddr());
%>

## 动态化

[Ajax](https://www.runoob.com/jquery/jquery-ref-ajax.html) (Asynchronous JavaScript And XML)是个思想，对应的浏览器接口实现对象是XMLHttpRequest(XHR)，其概念最早是微软提出的，目的是为了持续修改一个加载过的页面。随后被Mozilla、Apple和Google采纳。如今，该对象已经被W3C组织标准化。

Google 推出 Gmail 的时候(2004年)首次使用，页面在首次加载后，剩下的所有数据都通过AJAX来更新。从此改变了一切。以前每次都要从服务端请求新页面，比如登录成功之后，请求一个登录成功的html页面，现在前端可以通过Ajax进行数据交换，在不重新加载整个网页的情况下，对网页的某部分进行更新，直接显示登录成功，意味着单页Web应用成为可能。

有了Ajax，可以异步拿到数据，拿到之后，使用 [jQuery](https://www.runoob.com/jquery/jquery-examples.html) 修改DOM节点:

<!-- HTML -->
<p>Hello, <span id="name">Bart</span>!</p>
<p>You are <span id="age">12</span>.</p>

结果
Hello, Bart!
You are 12.

用ajax获取数据，然后用jQuery修改name和age节点的内容：

```javascript
var xhr = new XMLHttpRequest();
xhr.open('GET', 'example.com');
xhr.send();
   xhr.onreadystatechange = function(){
　　if ( xhr.readyState == 4 && xhr.status == 200 ) {
                  alert( xhr.responseText );
                  //从xhr.responseText中取出name和age
                  $('#name').text(name);
                  $('#age').text(age);
　　} else {
　　　　alert( xhr.statusText );
　　}
};
```

在HTML5的概念形成后，W3C开始标准化这个接口，08年提出了XMLHttpRequest Level 2草案。这个XMLHttpRequest的新版本，提出了很多有用的新功能。更详细的用法 [参考本文](http://www.ruanyifeng.com/blog/2012/09/xmlhttprequest_level_2.html) ：

- 可以设置HTTP请求的时限。
- 可以使用FormData对象管理表单数据。
- 可以上传文件。
- 可以请求不同域名下的数据（跨域请求）。
- 可以获取服务器端的二进制数据。
- 可以获得数据传输的进度信息。

具体用法可以参考 [@ali/lib-mtop](http://gitlab.alibaba-inc.com/mtb/lib-mtop/blob/master/src/core.js) 学习了解一下

## 模块化

有了动态更新页面的能力后，功能越来越多，代码越来越复杂，JavaScript却一直没有包引入和模块体系，无法将一个大程序拆分成互相依赖的小文件，再用简单的方法拼装起来。其他语言都有这项功能，比如 Ruby 的require、Python 的import，甚至就连 CSS 都有@import，但是 JavaScript 任何这方面的支持都没有，这对开发大型的、复杂的项目形成了巨大障碍。

为了解决这个问题，开发社区制定了一些模块加载方案，最主要的有 CommonJS 和 AMD 两种。

前者CommonJS的实现便是Node.js，它基于Chrome浏览器的V8引擎，构建了一套浏览器外的JS运行环境，提供了模块化规范，npm(node package manager)是它的模块化包管理器，支持发布管理模块，处理模块的依赖关系。

在没有Node.js的时候，js代码只能通过\<script>标签插进html去运行，单个的js文件离开了html什么都不是。如果一个网站功能很多，需要按照功能划分写15个js文件，插入15个\<script src="">去引那些js文件，还得注意引用顺序和插入的位置，一方面难以维护，一方面增加了网页加载时的请求数量。

有了Node.js之后，单个的js文件离开了html以后也可以在终端run起来，基于CommonJS的模块化标准实施，js有了引入和导出的概念，再也不用在html里写15个\<script src="">去引用js，只要插入一个作为入口的总script标签，另外的14个js文件都作为模块导出，并导入到这个入口的js。也可以把功能模块发布到npm上，供别的工程导入使用。

一旦js文件以\<script src="">的形式插入html，那么require、export、import之类的模块语法就会报错，因为这些模块语法是建立在node的环境下才有的，浏览器不认识这些语法，这就需要构建工具（webpack等）让我们插入一个script标签的同时，还允许我们在js文件之间使用export、import、require这些语法，并且非常智能地把这些js模块合并压缩成1个（或2个或以上）大大的紧实的js文件。

这里简单介绍了模块化从无到有，详细的介绍，有一篇单独的总结 [《前端的模块化》](https://www.atatech.org/articles/162016) 。

## 数据驱动

解决了模块化的问题之后，理论上来说，工程可以无限扩展了，那么页面的模块之间该如何组织和联动呢，这方面的最佳实践就是 [Flux](https://facebook.github.io/flux/) 的数据驱动思想。

以下面这个单页面场景为例，有三个大模块ABC，模块内又有小模块，关系如下：

> 1、B2影响A2模块和C101模块(图中黑线）
>
> 2、B1和B2模块影响A2模块(图中黄线)
>
> 3、C1影响B1模块(图中白线)

常规写法可能就是通过callback回调监听，或者写一个统一的消息中心，互相之间监听或者发送消息。

每一条关系线都需要开发者维护的，当关系复杂起来，不仅影响开发效率，而且不好维护，容易引发bug，假如后期加新需求或者调整需求，开发成本都是比较高的。

看下数据驱动的思想是如何解决这个问题的：

![image.png](https://oss-ata.alibaba.com/article/2023/11/62704e92-08f7-48c4-9e83-b3c4055d0127.png?x-oss-process=image/resize,m_lfit,w_1600/auto-orient,1/quality,Q_80/format,avif/ignore-error,1 "image.png")

页面上面所有的展示都是由数据决定的，和页面其他地方没有任何关系。页面之间每个模块，不用关心父子模块之间的关系，每个独立的模块都是由一个全局的model决定。模块依赖model中的数据，model中的数据改变，模块跟着改变，页面上所有的操作都是对数据的操作，业务逻辑全部都会聚集在model中，每个模块只需要监听关注的数据改变即可。

![image.png](https://oss-ata.alibaba.com/article/2023/11/b7a8412a-ea0a-443c-9299-a6e8c420c9af.png?x-oss-process=image/resize,m_lfit,w_1600/auto-orient,1/quality,Q_80/format,avif/ignore-error,1 "image.png")

用户对M1的页面一做了一个操作（action）让M1产生了改变M',这时M1变成了M2,对应的页面也由页面一刷新成了M2对应的页面二。同理，M2通过交互变成了M3,页面也会刷新成M3对应的页面三。

核心就是页面总是用model中的最新数据渲染自己，页面的行为使得model中的数据改变，数据改变会触发页面的渲染动作，从而数据驱动着页面刷新，无需关心模块直接的复杂关系。而且框架的虚拟dom会去比较每一次页面修改的最小diff，只重新渲染diff的部分，实现性能优化。

## 框架工具百花齐放

到这里，前端的基础已经非常完善，可以支撑项目需求了，前端工程师也可以疯狂写代码了，但是为了进一步提高开发效率，前端陆续有大量的框架出现，可以说是百花齐放。

UI组件库ant.design，开发框架React、Angular、Vue.js，开发语言Typescript，增强css功能的预编译器sass、Less，css转换工具postcss，代码分析工具ESLint，把高版本ES转译到低版本从而兼容浏览器的工具Babel...

应有尽有甚至有点眼花缭乱，有了完善的基础设施，可以支持复杂的单页应用和业务需场景，前端的需求也就也来越多，前端工程师也就诞生了。

## 问题和展望

再看下前端的发展史

看起来，前端到现在，已经非常完备了，那么相比于Native，还有哪些瓶颈呢

1、网络

Native的安装包自带资源，启动后省略了加载资源的时间，前端打开网页所有资源需要从0下载，自然要慢一点，不过随着5G的普及和网速的增长，这个差距会逐渐弥补掉。

2、API

Native可以直接使用系统的API，而前端运行在浏览器里，意味着受浏览器能力的限制，自然有些能力是缺失的，比如截屏录屏、访问文件系统等，不过感觉这个事情，应该由W3C牵头，把系统API逐步制定到标准中，补齐这部分差距。就像HTML5增强了自身能力，把Flash这些插件淘汰掉一样，或者未来的HTML678的某个版本，补齐了众多系统API，从而前端的能力再次极大提高。

3、性能

JS的单线程限制自然性能会有所差距，但是Workers的出现，以及WebAssembly的出现，可以把存量Native能力搬迁到web，随着CPU性能的进步，性能的差异或许也能逐渐缩小？

当然以上都是YY，或许有一天，能用js写的最终都会用js写，能搬到Web上来的，都会搬到Web上来？

从用户的使用体验来讲，不需要安装，打开即用，用完即走，不用关心版本，不用升级，体验真的会好很多。
