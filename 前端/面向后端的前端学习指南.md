## 背景

经常会有人讲全栈的概念，但真正能能做到全栈开发其实是非常难的，任何一个领域深耕，都需要投入巨大的精力。同时也有很多团队面临前端资源不足的情况，导致很多需求都排不上，但实际上有不少需求是比较简单的，尤其是中后台的页面。如果后端能学习一些前端的知识，能完成一些简单需求的开发，能很大程度上提高整体需求的交付效率，也算是多学习一门技能，毕竟技多不压身。

如果是五年前，可能还很难讲这个话题。前端各种框架、工具演进是非常快的，可能两个团队用到的技术栈就有很大差异，甚至一个团队内部多个项目都完全不一样。我曾经有段时间，同时维护基于react、angularjs、ejs的几个项目，用到的组件库、构建工具和命令，都完全不同。经过这几年的发展，集团内react已经完全大一统，组件库和工具也慢慢统一，不再是以前大混战的情况了。而且目前lowcode框架也越来越成熟，上手开发简单前端页面的也越来越容易了。

对于想要学习前端的后端同学来说，这是一个非常好的时机。

## 目标

可以先定一个小目标，学习一些前端知识之后能做到

1. 能独立完成简单页面的开发
2. 有组件复用意识，能开发一些简单的公用组件
3. 有一定问题定位和排查的能力

## 注意

这里讲的不是如何系统学习前端，也不是一个大而全的指南，而是如何让后端同学快速学习前端知识，实现上述目标。重点关注怎么快速理解一些前端的概念，哪些是必须要理解的，哪些其实可以先不考虑。

总的来说就是学习语言，HTML没有太多要注意的，CSS是比较难的，前期了解即可，不需要太深入，最主要的是JS的学习，一门动态解释型的语言，语法也是类C的，大部分的代码还是能直接看明白的，同时需要关注如下的点

### this关键字和函数调用(call/apply/bind)

我们有的时候不太严格区分函数和方法，严格来说java里面都是方法，在JS里面的可以说都是函数。函数是独立存在的东西，并不属于任何一个对象，这一点是非常重要的。JS里面的 `this` 跟java里面的 `this` 不是一个概念，如果照搬的话，很多地方都难以理解。在react写的代码里面，会有大量类似 `this.someFunction.bind(this)` 的代码，如果不太了解这个机制，看上去非常的奇怪。大部分的后端同学在接触react的时候，都会有这样的疑问，为什么不能直接写 `this.someFunction` 。

并且因为是动态语言，并不需要参数能够对应，函数里面是可以通过 `arguments` 获取到所有的参数，所以可以写出如下的代码，很多库都会用这样的方式实现函数重载的效果。

```javascript
function foo() {
    console.log(...arguments);
}
foo(1, 2);
foo('a', 'b');
```

相关的文章非常多了，这里不详细讨论。

### 异步编程 callback / promise / async await

前端页面是离不开跟后端交互的，在JS里面可以认为所有的HTTP请求都是异步非阻塞的，Java也是支持异步编程的，只不过并没有从语法层面支持（不支持类似 async/await 关键字）。

很多人写了很多年Java可能也没怎么写过异步的代码，Java9定义了响应式编程的API，Spring5全面支持响应式异步编程（Reactor/WebFlux），HSF之类的本身都是支持异步返回的，但实际上用得并不多，反而Android开发者很早就开始用RxJava来处理各种交互和请求。

总的来说同步代码清晰，便于理解和定位问题，异步代码效率会更高一些。

异步就一定离不开callback，但callback多了之后，代码非常难以维护（callback hell），会出现类似的代码（假设要顺序发起三个请求）

```javascript
request(url1, () => {
    request(url2, () => {
        request(url3, () => {
            doSomething();
        })
    })
})
```

之后出现了promise模式，通过then的方式

```javascript
request(url1)
.then(() => request(url2))
.then(() => request(url3))
.then(() => doSomething())
```

再往后出现了 async 和 await，基本看上去和同步代码类似了（本质上还是异步）

```javascript
await request(url1);
await request(url2);
await request(url3);
doSomething();
```

Promise类似Java里面的 `CompletableFuture` ，在学习的时候，可以先试试用Java的方式来学习，试着去理解异步的代码是怎么去运行的。可以去构造一些请求的场景，例如顺序发起请求，并发发起请求（可以试试手动实现CompletableFuture.allOf/anyOf），可以参考下面的代码。

```java
/**
 * 模拟请求
 */
private static void request(String url, Consumer<String> success) {
    // 简单示意
    new Thread(() -> {
        try {
            TimeUnit.SECONDS.sleep(1);
        } catch (InterruptedException e) {
            throw new RuntimeException(e);
        }
        System.out.println("request: " + url);
        success.accept("{}");
    }).start();
}

/**
 * 模拟请求
 */
private static CompletableFuture<String> request(String url) {
    // 异步请求包装成future(promise)
    CompletableFuture<String> future = new CompletableFuture<>();
    request(url, future::complete);
    return future;
}

public static void main(String[] args) {
    // callback 顺序发起请求
    CompletableFuture<String> future = new CompletableFuture<>();
    request("url1", r1 ->
        request("url2", r2 ->
            request("url3", r3 -> {
                System.out.println(r3);
                future.complete(r3);
            })
        ));
    future.join();// 等待结束
    // Promise.then 顺序发起请求
    request("url4")
        .thenCompose(r -> request("url5"))
        .thenCompose(r -> request("url6"))
        .thenAccept(System.out::println)
        .join();
    // Promise.all 并行发起请求
    CompletableFuture
        .allOf(request("url7"), request("url8"), request("url9"))
        .join();
}
```

在前端的项目里面，异步编程非常重要，不要都当作同步代码来写，可能会导致滥用await。

### 线程模型

可以简单认为，一个页面下所有的JS是单线程执行的，所以不太需要考虑并发修改数据的问题。不要害怕多个callback里面修改同一个数据。

### 类型转换 == ===

js 有很多隐式的类型转换，也会导致一些看上去有些奇怪的语法，例如 `someFunction && someFunction()` 和 `{someFlag && <div></div>}` 。

具体的规则不需要刻意去记，最常用的就是字符串的判断直接 `if (someString) {}` ，不需要类似java里面 `if (someString != null && !someString.isEmpty())` 。  
还需要简单区分一下 `undefined` 和 `null` 的区别，知道 `==` 和 `===` 的区别。

### ES6

可以简单把ES6当作JS的一个版本，类似Java8，里面也新增了很多内容，例如箭头函数、字符串模板、解构、扩展、Class等，可以看看阮一峰的 [ES6 入门教程](https://es6.ruanyifeng.com/) 。

### 作用域 var / let / const

这个简单了解就可以了，可以记一个简单的规则，不要用 `var` ，能用 `const` 就用 `const` 。

## 运行环境

运行环境指最终运行JS代码的地方，对应到后端就是JRE，JS的代码主要运行在浏览器和NodeJs里面。

### 浏览器

浏览器是一个非常重要的内容，需要

1. 了解浏览器的安全模型，要知道有一些事情在浏览器里面是做不了的，要了解为什么会有跨域的问题，如何做跨域请求（CORS/JSONP）
2. 前端缓存体系，了解浏览器是怎么缓存静态资源的，要知道什么时候要刷新缓存，什么时候不用刷缓存，知道怎么看某个请求是否走了缓存
3. 会使用开发者工具
4. 了解DOM，可以简单理解为是浏览器提供给你的一系列API，具体API可以在用的时候再去查询
5. 了解浏览器的工作原理

大概类似于学习后端要学习linux一样。

### NodeJs

浏览器环境是受限的，很多东西都无法使用，例如文件、网络等，NodeJs是一个完整的运行环境，可以直接开发完整的后端应用。一般不太需要太了解NodeJS，需要简单了解npm包管理机制和package.json文件，对应到后端就是 maven 和 pom.xml。

## 框架

这里只考虑React，可以认为是Spring之类的框架，学习资料也非常多，基本上遇到的问题都可以搜到。可以按照 [官方文档](https://react.docschina.org/) 来学习。

1. 需要了解JSX语法
2. 要理解react的数据绑定
3. 理解 props 和 state
4. 知道组件之间如何通讯，传递数据
5. 了解React的思想 UI = f(state)
6. 了解React的生命周期

## 组件库

提到代码复用，一般会说继承和组合，而从前端开发的角度来说，最主要是通过组合的方式实现复用。组件是一部分可被复用的页面元素，比如按钮、时间选择、表格等。而页面就是由很多的组件构成的。

当拿到一个组件库，最快速的方式，就是每个组件都试试，试试不同参数的效果，而且。非常容易，就是试。

## 工程化（了解即可）

这部分内容了解即可，很多项目其实在初始化的时候，都做好了。

一般在需求开发的过程中，不要需要关注模块加载，打包工具，构建和发布的细节，之后只需要按照说明执行相关的命令即可。

## 前端思维

这部分感觉更多是作为一个用户和产品的视角，大部分中后台页面是没有交互设计的，要逐步养成下面的思维

1. 一个应用的多个页面之间，风格要尽量统一，可以团队内制定一些简单的规范
2. 要有让页面好看、好用的意识，边距、布局是否合理，交互是否合理（比如下拉选项多了的话，应该加上搜索）
3. 输入校验的意识

## 暂时不需要关心

还有一些话题，也是比较重要的，但可以先不考虑，包括

1. 一些复杂的CSS问题，比如实现各类布局和效果
2. 动画相关
3. 原型链 Function / Object / \_\_proto\_\_ / prototype
4. 比较底层的知识
5. 性能相关的问题，只要没有大表格，大部分情况下不太需要考虑性能问题
6. 工程化相关的问题，各种预编译和打包工具

## 低代码平台

除了源码开发，目前低代码开发平台也越来越成熟，在 [纪元](https://www.atatech.org/articles/174070) ，配合服务编排的能力，也可以迅速搭建出来一些简单页面，实现一些前端的需求。

## 总结

全栈开发可以开阔自己的技术视野，提出一些更全面、合理的解决方案，能够在一定程度上提升需求交付的效率。

但全栈也确实是比较难做到的，需要投入大量的精力，虽能能总结出来一些提纲和指南，但总的来说，学习没有什么捷径，要多练习、多思考。
